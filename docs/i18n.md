# Translations (i18n)

CommerceOS uses **i18next** (with react-i18next), the standard React
translation stack. Texts live in plain JSON files, one per language and
namespace, which translation platforms (Crowdin, Lokalise, Weblate, …) read
and write directly.

| App | Files | Language comes from |
|---|---|---|
| Storefront (shopper texts) | `storefront/src/i18n/locales/<lang>/shop.json` | the channel's **Storefront language** (`storefront_locale`) |

Languages today: `en` (source), `pt-BR`, `nl`.

## File format

```json
{
  "cart": {
    "empty": "Your cart is empty.",
    "quantityOf": "Quantity of {{name}}",
    "items_one": "{{count}} item",
    "items_other": "{{count}} items"
  },
  "account": { "signInFirst": "Please <link>sign in</link> to see your account." }
}
```

- **Placeholders** are `{{name}}`; keep them exactly as in English.
- **Plurals** use `_one` / `_other` suffixes (plus `_zero`, `_few`, `_many`
  where a language needs them) and are chosen from `count`.
- **Tags** like `<link>…</link>` or `<strong>…</strong>` wrap words that the
  code turns into links or bold text; keep them, move them freely.
- A **blank** text (`""`) falls back to English, so a half-translated
  language still works.

## Everyday tasks

Run these in the app folder (e.g. `storefront/`).

**Add or change a text in the code**

1. Use it in code: `const { t } = useTranslation()` then `t('cart.empty')`.
   Keys are typed from the English file, so a typo doesn't compile.
2. `npm run i18n:extract` adds new keys to every language file (English gets
   the key as its text, other languages get `""`) and removes unused ones.
3. Write the English text in `en/shop.json`, translate the others.
4. `npm run i18n:check` lists what's still missing.

Always call `t('literal.key')` with a literal key: the extractor can't see
keys built at runtime and would delete them.

**Fix a translation:** edit the JSON file, run `npm run i18n:check`.

**Add a language**

1. `npm run i18n:add de` creates `locales/de/*.json` with blank texts.
2. Translate them (or upload to your translation platform); check with
   `npm run i18n:check`.
3. Register the language:
   - `src/i18n/locale.ts`: add it to `LOCALES`, `LOCALE_NAMES`, `INTL_LOCALE`
   - `src/i18n/resources.ts`: import its files
   - `i18next-parser.config.js`: add it to `locales`
   - backend: `domain/channels/storefront_locale.go`, the `StorefrontLocale`
     enums in `api/integrations/openapi.yaml` and `api/storefront/openapi.yaml`,
     and a migration extending `sales_channels_storefront_locale_check`.
4. The catalog test then requires it to be complete.

## Not translated (yet)

Shopper emails (sign-in link, newsletter) and backend error messages are
